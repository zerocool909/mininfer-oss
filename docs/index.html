Don’t ask which model is best. Ask which is capable enough, at the lowest effective cost.

min(Infer) collects evidence from provider APIs, catalogs, pricing pages and benchmarks, then routes each request to the cheapest deployment that clears the bar for that task. Prefer free. Pay only when necessary.

01The idea

A decision engine, not a load balancer.

The LLM market moves weekly. Models launch, get retired, change price, hit rate limits, or appear on a new gateway with a free tier. The same weights can cost nothing on one provider and a lot on another.

So min(Infer) keeps three things apart that most routers blur together: the model (what it can do), the deployment (provider, price, limits, latency, availability), and the task (what has to be true for an answer to count). A request is routed by filtering deployments against the task, then picking the cheapest survivor.

The registry describes what exists. Live evidence determines what is usable.

02The ledger

“Free” is not the same as cheap.

Ranking runs on cost per success: expected spend divided by the lower-bound probability the model actually completes the task. A model that fails half the time costs more than its sticker price says.

The shortlist is 2–3 primaries plus 2 backups, one backup reserved for an untested arm, and a last resort that is tried only when the chain is exhausted — so a request can run out of free arms but not out of an answer.

03Earning trust

Two wins out of two is not a track record.

The router scores each model per task with the Wilson lower bound of its success rate, seeded with a benchmark prior so cold starts aren’t blind. Small samples get penalised until evidence accumulates. Try it:

Black tick: raw rate. Bar: lower bound at z = 1.96. Dashed line: the task’s quality floor.

Untried free models get their evidence without risking users. A small slice of traffic is duplicated in the background to an untried arm after the real answer has already been sent. An LLM judge scores the shadow reply, the result is recorded as a judge_trial observation, and once the lower bound clears the floor the model graduates to real traffic. Nobody waits on it and nobody is billed for it.

04Heartbeat

A dead key should fail on a timer, not on your request.

The registry says what exists. Only a live call says what still works. Left alone, the router finds a revoked key or an unreachable host the expensive way — by spending a request on it. The optional warm tier asks first, on a cadence, and keeps the answer warm.

groq · healthy · 12 models · 316 ms openrouter · healthy · 464 models · 449 ms a-provider · auth_error

Each check is a provider’s own GET /models: cheap, and enough to prove reachability (DNS and TLS) and that the key is still accepted, without inventing a chat model to call. The verdict is recorded per provider — ok, auth_error, network_error, or the HTTP status — with latency and model count.

  1. Off until you ask.

    The probe is opt-in, toggled from the dashboard’s Settings → Providers card. A plain docker compose up makes no scheduled upstream calls it was not asked to make.

  2. Cheap, on a cadence.

    A key is checked every five minutes by default, down to 30 seconds. Run now probes every configured provider on demand.

  3. The router reads it.

    A provider whose most recent check failed is dropped from the candidate pool, so the next request skips it instead of spending itself on it. The verdict expires after 15 minutes — switching the probe off can never exclude a provider forever.

05One request

What happens between the prompt and the first token.

# POST /v1/chat/completions model=auto classify intent=summarise confidence=0.82 (local, no paid call) filter 214 deployments → 37 context · modality · auth · quota headroom · probe health score cost ÷ p_lb per candidate, free-first cap no model above 60% of this task’s traffic dispatch openrouter:qwen/qwen3.8-27b:free 429 → exhausted for this minute, same request moves on dispatch vercel:poolside/laguna-s-2.1-free first byte in 412 ms record evidence written · reputation updated · shadow trial queued (5%)

  1. Classify locally.

    Intent comes from heuristics and a local model, so routing doesn’t burn a paid call to decide where to spend. Ambiguous prompts merge the profiles of the competing tasks and satisfy both.

  2. Filter on hard constraints.

    Context length, modality, credentials, quota headroom, and live health. Headroom is the minimum of the configured limit and what the provider’s live x-ratelimit-* headers last said; a provider whose last warm-tier probe failed is skipped until it recovers.

  3. Rank, then cap.

    Cost per success decides the order. No single model may take more than 60% of a task’s traffic, and manual pins expire after 24 hours, so the system can’t fixate.

  4. Fail over before the first byte.

    A 429, timeout or dropped connection moves the same request to the next ranked arm. Once streaming starts the router is committed, because a half-sent stream can’t be unsent.

  5. Write down what happened.

    Every outcome, including a 404 for a retired model, becomes evidence. The next decision is made against it.

06For agents

Most of an agent’s calls aren’t reasoning calls.

Between the two steps that need judgement sit dozens that don’t: expand a tool result, classify a branch, pull fields out of a page, choose the next action, format arguments, summarise what came back, retry a 429. Multiply them by every run and the bill starts tracking the number of steps, not the difficulty of any one of them.

min(Infer) is the seam for that work. Point the whole agent at one OpenAI-compatible endpoint and let each step be routed on its own merits — the frontier model is not removed, it is reserved for the calls that need it.

Agent stepWhat it needsWhere it lands
Summarise a tool resultruns constantlyshort output, no toolsthe first free tier that clears

Plan or synthesise a hard answerrare, decisivereasoning, 16kthe frontier arm — and only here

The task decides which model runs — not the caller, and not a second, lesser endpoint.

The free factor is the mechanism, and it is measured. Free-tier deployments win whenever they clear the task’s bar, and the router reads their quota headroom, so it steps to the next arm before the free one 429s. Ranking runs on cost per success, so a free model that fails half the time is priced as expensive as it is — what survives is what keeps completing the work. At agent scale that puts the bulk of the steps at zero marginal cost and keeps the paid tier for the few that earned it.

Every step names its author: the response carries the model and provider that answered, and the decision log keeps the shortlist and the rejection reasons, so “why is the agent spending this?” has a per-call answer, not a per-invoice one.

07Principles

Why it behaves the way it does.

Identity is separate from economics
The same weights are different deployments with different prices, limits and reliability. They are scored independently.
Prices are beliefs with a history
Each price is stored with when it was adopted, so a past decision is judged against what was known then. Silent price changes raise anomalies.
Budgets are reserved, not observed
A session cap reserves prompt estimate + max_tokens before the call, so a limit is a ceiling rather than a suggestion you overshoot by one request.
An error is evidence
When a provider retires a model, the 404 marks it uncallable and traffic reroutes. Nobody has to edit a config file at night.
Humans are a signal too
Compare mode streams two models over one connection. Your pick is recorded as a weak subjective observation alongside the automatic ones.
Every answer names its author
The reply shows which model and provider produced it, what else was shortlisted, and what it cost, speed and latency were.
A dead key fails on a timer
The optional warm-tier probe checks every configured provider on a cadence, so a revoked key or a down host leaves the candidate pool before a request spends itself on it.
Failures are attributed, not just counted
Every request is recorded whatever the outcome. A 429 or timeout is usually the provider, not the model, so the rollup demotes the gateway once instead of rediscovering the outage arm by arm — and a verdict needs a minimum sample before it is issued.
No model becomes the default
Traffic is capped per task, and the agents rotate across a free-first chain rather than pinning to whichever arm answered last. One free tier is never exhausted while the others sit idle.
08Run it

Point any OpenAI-compatible client at it.

# clone and install
git clone https://github.com/zerocool909/mininfer-oss.git
cd mininfer-oss
python3 -m venv .venv && source .venv/bin/activate
pip install -e .

# copy .env.example to .env, add the provider keys you have, then:
mi proxy --port 8765
curl http://127.0.0.1:8765/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Summarise this"}]}'

Open http://127.0.0.1:8765 for the dashboard: the model registry with untried, trialing and proven states, the chat playground, and the decision log. The Settings → Providers tab also carries the warm-tier toggle and a live health badge per provider. The README covers configuration, quotas and the full API contract.
