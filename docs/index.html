Core Capabilities

A Decision Engine, Not a Dumb Load Balancer

min(Infer) separates the model (what it can do), the deployment (what it costs here), and the task (what has to be true). Here is what makes it unique.

  • Prefer Free First

    Dispatches to verified free tiers as long as they clear the task's quality floor. Pays only when free capacity is insufficient.

  • Evidence, Not Vibes

    Every pricing tier, token limit, and capability is an immutable, time-stamped record with traceable source provenance.

  • Task-Aware Quality Floors

    Uses hard capability gates and Wilson score lower bounds, avoiding single blended benchmark averages that misroute.

  • 100% Explainable

    Every response names the winning author and records why every rejected candidate failed to make the cut.

  • Zero Data Retention

    Runs on your own provider credentials. Prompt and response bodies are never stored or logged by default.

  • Drop-in OpenAI API

    Point any client, LangChain, Cursor, or agent loop at http://127.0.0.1:8765/v1 with model: "auto".

  • Dual Database Backends

    Local SQLite out of the box with zero setup; seamless Postgres connection via DSN for multi-tenant production teams.

  • Failover Before First Byte

    Catches upstream 429s, DNS timeouts, or dropped connections and transparently reroutes before streaming commits.

Conceptual Architecture

Three Things Most Routers Blur Together

A single model weight can cost nothing on one gateway and a fortune on another. min(Infer) manages them as distinct entities.

01 · The Model

What It Can Do

Modalities (text, vision, tools), architecture parameter size, context capacity, and benchmark priors. The pure cognitive artifact, independent of provider host.

02 · The Deployment

What It Costs Here

Endpoint URL, pricing tier ($/token), rate-limit headroom, probe availability, and live DNS latency. Scored and tracked as an independent operational asset.

03 · The Task

What Has To Be True

The required capabilities (JSON schema, tool calling, 32k window) and the quality threshold an answer must clear to be counted as a success.

The Economic Ledger

Request Lifecycle

What Happens Between Prompt and First Token

A look under the hood at the 5-stage decision pipeline executed on every incoming request.

  1. 1. Classify Locally

    Determines intent via heuristics & fast local models. Never spends a paid upstream call to decide where to route.

  2. 2. Hard Filtering

    Eliminates models lacking context size, required tools, modality, or quota headroom based on live provider rate-limit headers.

  3. 3. Wilson Scoring

    Ranks surviving candidates by cost-per-success. Enforces a 60% traffic cap per arm so no single gateway becomes a monopoly.

  4. 4. Pre-Byte Failover

    If an arm encounters an unexpected 429 or network disconnect, it immediately falls over to candidate #2 before streaming begins.

  5. 5. Write Evidence

    Records prompt latency, token throughput, and success status into the local ledger to refine the next routing decision.

Design Philosophy

Architectural Principles

Built for platform engineers who need predictable, explainable, and cost-capped AI infrastructure.

Identity ≠ Economics

Identical weights on different providers have drastically different uptime, latency, and pricing. They are evaluated as separate deployments.

Budgets Are Reserved First

Session caps reserve estimated token allowances before the request dispatches, ensuring hard limits are never exceeded by trailing requests.

Prices Are Beliefs With History

Every pricing tier is versioned with the date it was observed. Unannounced upstream price hikes raise immediate anomaly alerts.

An Error Is Valuable Evidence

When a provider sunsets a checkpoint, the resulting 404 permanently updates the registry without requiring manual config updates at 2 AM.

Failures Are Attributed

A 429 is attributed to the provider gateway, not the underlying model architecture, preventing unnecessary cascading invalidations.

Anti-Concentration Caps

No model may consume more than 60% of a task's traffic. Ensures exploration bonuses keep fallback arms warm and prevents vendor lock-in.

Drop-In Integration

Two Lines of Code to Switch Any Client

min(Infer) implements the standard OpenAI chat completions spec. Change only the base_url.

from openai import OpenAI

# Point directly to your local or deployed min(Infer) gateway
client = OpenAI(
    base_url="http://127.0.0.1:8765/v1",
    api_key="mi-local"  # or use your min(Infer) master token
)

response = client.chat.completions.create(
    model="auto",  # min(Infer) analyzes the prompt & picks the cheapest capable arm
    messages=[{"role": "user", "content": "Summarize this release note..."}]

print(response.choices[0].message.content)

Frequently Asked Questions

Clear Answers to Common Questions

Do I need to provide my own API keys?
Yes. min(Infer) operates on user-supplied provider credentials stored locally in your .env file or passed per request via X-User-API-Keys. However, min(Infer) includes 8 keyless catalog sources, allowing you to bootstrap the registry and discover deployments without any keys upfront.
How is this different from LiteLLM, OpenRouter, or Portkey?
Most proxies are either static aggregators or round-robin load balancers. min(Infer) is a constraint-satisfaction decision engine: it tracks live rate limits, tests model availability with active health probes, enforces task quality thresholds using statistical Wilson confidence bounds, and minimizes cost-per-success rather than simply forwarding traffic.
Does min(Infer) store my prompts or responses?
No. By default, prompt and response payload bodies are never written to disk or transmitted to any third party. Only operational telemetry (latency, token count, upstream HTTP status, and winning model identity) is recorded in your local SQLite/Postgres database.
What happens if a free model hits a 429 rate limit?
min(Infer) reads provider x-ratelimit-* response headers dynamically. If a model is close to saturation, or if an unexpected 429 occurs, min(Infer) catches it before first-byte streaming begins and transparently dispatches the prompt to candidate #2 on the shortlist.
Can I pin specific models for sensitive workloads?
Yes. In addition to model: "auto", you can request specific models directly (e.g. model: "claude-3-5-sonnet") or pass explicit constraints like task: "code" or quality_floor: 0.90.

min(Infer) is 100% open-source under the permissive MIT License. You can run it locally, deploy it in private VPCs, or bundle it into commercial agent architectures without restriction.
